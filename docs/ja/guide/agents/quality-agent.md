# Quality Agent

> **エージェント詳細** · [User Guide](../00-introduction.md) › [エージェント](../06-agents.md) › [詳細](README.md) · 技術リファレンス: [quality-agent](../../reference/agents/quality-agent.md)

aidlc-quality-agent は QA エンジニア兼性能スペシャリストです。テスト戦略を決め、テストスイート（ユニット、統合、契約、セキュリティ）を生成し、受け入れ基準に対するカバレッジを検証し、負荷テストを設計・実行し、非機能要件の目標を検証します。実装したユニットが受け入れ基準を満たし、システム全体が品質ゲートを通ることを見ます。

リードは 2 ステージ（Construction 1、Operation 1）、サポートは追加 3 ステージです。ビルドツール、テストコマンド、性能テストのために Bash を持ちます。

## リードするステージ

| ステージ | フェーズ | 内容 |
|-------|-------|-------------|
| 3.6 Build and Test | Construction | ビルドを走り、テストスイートを生成・実行し、品質ゲートを検証する |
| 4.6 Performance Validation | Operation | 負荷テスト、NFR 検証マトリクス、キャパシティ計画 |

## サポートするステージ

| ステージ | フェーズ | 寄与 |
|-------|-------|-------------|
| 2.2 Practices Discovery | Inception | 互いに見えないテスト姿勢のスポーク。自分の寄与ファイルを書く |
| 2.4 User Stories | Inception | モブでのテスト可能性と受け入れ基準の声。自分の寄与ファイルを書く |
| 3.2 NFR Requirements | Construction | テスト可能な品質属性シナリオを定義する |

## 動きのイメージ

動いているときは、ビルド手順とテストスイートを生成し、実装コードに対して実行します。Build and Test では、プロジェクトのビルドシステムを走り、ユニットテスト、統合テスト、プロジェクトに合う追加のテスト種別を実行します。合否、カバレッジ指標、品質ゲートの状態を報告します。

Operation の Performance Validation では、負荷テストを設計・実行し、NFR 目標（レイテンシパーセンタイル、スループット、可用性）を検証し、目標と実測を比べる NFR 検証マトリクスを出します。

## 協働の仕方

受け入れ基準付きユーザーストーリーは aidlc-product-agent、NFR 目標は aidlc-architect-agent、実装コードは aidlc-developer-agent から受け取ります。セキュリティテスト要件では aidlc-devsecops-agent、CI 統合では aidlc-pipeline-deploy-agent と組みます。テスト結果と性能ベースラインは aidlc-operations-agent へ渡します。

## 原則

- 実装ではなく、要件をテストする
- テストピラミッドに従う。速いユニットテストを多く、統合は少なめ、E2E は最小
- 欠陥を見つけたら、直す前に再現するテストを書く
- テストは実行順や共有状態に依存しないこと
- カバレッジは指針であり、目標ではない。意味のない断言 100% より、考えたテスト 70%
