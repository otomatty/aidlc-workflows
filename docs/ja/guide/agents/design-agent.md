# Design Agent

> **エージェント詳細** · [User Guide](../00-introduction.md) › [エージェント](../06-agents.md) › [詳細](README.md) · 技術リファレンス: [design-agent](../../reference/agents/design-agent.md)

aidlc-design-agent は UX/UI デザイナーです。Ideation ではワイヤーフレームとコンセプトスケッチを出し、Inception ではインタラクション仕様付きの高忠実度モックへ育てます。情報アーキテクチャ、ナビゲーション、レスポンシブ、アクセシビリティ要件を決めます。UI のないプロジェクトでは、システムコンテキスト図と API 体験の設計を出します。

リードは 2 ステージ、サポートは 2 ステージです。利用者向けの画面が、使える、アクセシブル、デザインシステムの基準に揃っていることを見ます。

## リードするステージ

| ステージ | フェーズ | 内容 |
|-------|-------|-------------|
| 1.6 Rough Mockups | Ideation | 低忠実度のワイヤーフレームとコンセプトの可視化 |
| 2.5 Refined Mockups | Inception | インタラクション仕様とアクセシビリティ付きの高忠実度モック |

## サポートするステージ

| ステージ | フェーズ | 寄与 |
|-------|-------|-------------|
| 2.4 User Stories | Inception | インタラクションの詳細と UX 受け入れ基準でストーリーを厚くする |
| 2.6 Domain Design | Inception | UI コンポーネント仕様を足す |

## 動きのイメージ

動いているときは、画面レイアウト、ユーザーフロー、インタラクションパターンを Markdown で詳しく書きます。対象デバイス、アクセシビリティ要件、デザインシステムの好みを聞きます。インタラクションは、具体的な画面状態と遷移で書きます。読み込み、成功、エラー、空、部分的な状態です。

## 協働の仕方

意図とユーザーストーリーは aidlc-product-agent、コンポーネントの制約は aidlc-architect-agent から受け取ります。モックとインタラクション仕様は、実装のために aidlc-developer-agent へ、UX 受け入れテストのために aidlc-quality-agent へ渡します。

## 原則

- スキャンしやすさ。重要な操作はすぐ見えること
- 一貫性が認知負荷を下げる。インタラクションパターンは予測できること
- エラーメッセージより、エラーそのものを起こしにくくする
- WCAG 準拠は最低ラインであり、伸ばし目標ではない
- 最悪ケースから設計する。空、エラー、遅い回線
