# Operations Agent

> **エージェント詳細** · [User Guide](../00-introduction.md) › [エージェント](../06-agents.md) › [詳細](README.md) · 技術リファレンス: [operations-agent](../../reference/agents/operations-agent.md)

aidlc-operations-agent はサイト信頼性エンジニア兼インシデントマネージャです。デプロイしたシステムが、観測でき、耐障害性があり、継続的に良くなることを見ます。運用層を持ちます。CloudWatch のダッシュボードとアラーム、X-Ray トレーシング、SLO 追跡、インシデント対応ランブック、カオスエンジニアリングによる検証です。いちばん大事なのはフィードバックループを閉じることです。本番の知見を Ideation へ戻し、次の反復へつなぎます。

リードは Operation フェーズの 3 ステージです。監視のセットアップ、ランブックスクリプト、診断ツールのために Bash を持ちます。

## リードするステージ

| ステージ | フェーズ | 内容 |
|-------|-------|-------------|
| 4.4 Observability Setup | Operation | ダッシュボード、アラーム、トレーシング、構造化ログ、カスタムメトリクス |
| 4.5 Incident Response | Operation | SSM ランブック、インシデント計画、エスカレーションマトリクス、オンコール体制 |
| 4.7 Feedback & Optimization | Operation | SLO レポート、コスト分析、ドリフト検出、フィードバックループ |

4.6 Performance Validation のリードは aidlc-quality-agent です。このエージェントが 4.4 で置く運用テレメトリとベースラインは、その仕事へ非公式に流れますが、4.6 の正式なサポートエージェントではありません。

## サポートするステージ

なし。aidlc-operations-agent はリード専用です。他エージェントのステージはサポートしません。リードはすべて Operation にあり、そこでライフサイクルのループを閉じます。

## 動きのイメージ

動いているときは、監視の好み、SLO 目標、インシデント対応プロセス、オンコール体制を聞きます。出すのは、CloudWatch ダッシュボードの設定、しきい値と通知先付きのアラーム定義、X-Ray トレーシングのセットアップ、よくある場面（サービス再起動、キャッシュフラッシュ、フェイルオーバー）の SSM ランブック、重大度定義とエスカレーション経路です。

最後のステージ、Feedback & Optimization では、本番メトリクスを分析し、最適化の機会を拾い、運用知見を次の開発サイクルの aidlc-product-agent へ戻すフィードバックループ文書を出します。

## 協働の仕方

用意されたインフラは aidlc-aws-platform-agent、デプロイされたサービスは aidlc-pipeline-deploy-agent から受け取ります。性能ベースラインと SLO 検証では aidlc-quality-agent、アプリケーション層のログ改善では aidlc-developer-agent と組みます。フィードバックレポートが Operation から Ideation への橋になり、ライフサイクルを一周させます。

## 原則

- テレメトリは広く取るが、アラートは利用者影響があるものだけ。アラート疲れは対応を鈍らせる
- SLO が信頼性の目標。ほかはそこから導く
- インシデントは学びの機会。非難のないポストモーテムが、インシデントを改善へ変える
- 未検証の耐障害メカニズムは仮定。カオスエンジニアリングで確かめる
- Ideation に戻らない本番知見は、無駄になった学び
- 手作業の運用負荷はなくす。繰り返せるランブック手順はすべて自動化する
