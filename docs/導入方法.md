# AI-DLC Workflows 導入方法

対象バージョン: **v2.8.2**（GitHub Latest）。2026-09-14 時点の [awslabs/aidlc-workflows](https://github.com/awslabs/aidlc-workflows) に基づきます。

この文書は **Claude Code** と **GitHub Copilot** への導入手順だけをまとめたものです。使い方・段階・エージェントの詳細は文末の公式ガイドを見てください。他ハーネスは [他ハーネスで動かす](ja/guide/harnesses/README.md) です。

## 導入の考え方

2.8 からは **ネイティブの `aidlc` コマンド** が正です。インストーラが全ハーネスのランタイムを入れ、プロジェクトでは `aidlc config` がシェルを投影します。Bun も Node.js も不要です。リポジトリの `dist/` を手でコピーする方法は、メンテナの開発用です。

| ハーネス       | 最低バージョン                     | config の値 | 起動     |
| -------------- | ---------------------------------- | ----------- | -------- |
| Claude Code    | （CLI 本体）                       | `claude`    | `/aidlc` |
| GitHub Copilot | CLI ≥ 1.0.74 / VS Code ≥ 1.130 | `copilot`   | `/aidlc` |

推奨モデルは **Claude Opus 4.8** です。弱いモデルではレビューや承認ゲートが省略されがちです。

## 共通の前提

ホストハーネスは、開く前に入れて認証します。ネイティブの AI-DLC 自体に Git、Bun、Node.js は不要です。

```bash
# macOS / Linux / WSL
curl -fsSL https://github.com/awslabs/aidlc-workflows/releases/latest/download/install.sh | sh
```

```powershell
# Windows PowerShell
irm https://github.com/awslabs/aidlc-workflows/releases/latest/download/install.ps1 | iex
```

新しいシェルで `aidlc` が見つからないときは、インストーラが出した PATH の指示に従います。版のピン、オフライン、アンインストールは [Install and Lifecycle](ja/guide/18-install-and-lifecycle.md) です。

モデル認証はハーネスごとです。

- Claude Code: 配布設定は **AWS Bedrock**
- GitHub Copilot: GitHub ログインまたは BYOK

## ハーネス別の導入

以下の `your-project` は、AI-DLC を入れたいアプリケーションのルートです。

### Claude Code

Claude Code を入れます。

```bash
# macOS / Linux
curl -fsSL https://claude.ai/install.sh | bash
```

```powershell
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
```

macOS なら `brew install --cask claude-code` でもよいです。`claude --version` で確認します。

プロジェクトを設定します。

```bash
cd your-project
aidlc config --harness claude
aidlc doctor
```

`claude` を起動し、セッション内で `/aidlc --doctor`、続けて `/aidlc <やりたいこと>`。プロジェクトフックの承認を求められたら承認し、**セッションを完全再起動**します。`/clear` では足りません。

出荷の Claude 設定は Bedrock（`AWS_REGION=us-east-1`）です。初回前に AWS アカウントで Anthropic モデルアクセスを有効にし、SDK の認証チェーンにクレデンシャルを載せます。詳細は [導入 — AWS Bedrock の設定](ja/guide/01-getting-started.md#aws-bedrock-setup) です。

### GitHub Copilot

Copilot CLI ≥ 1.0.74 および / または VS Code ≥ 1.130。1 回の導入で CLI と VS Code agent mode の両方に効きます。モデルピンは無く、サインインまたは BYOK です。

```bash
copilot --version
```

```bash
cd your-project
aidlc config --harness copilot
aidlc doctor
```

config のあと:

- フォルダを信頼する。対話プロンプトを承認するか、`~/.copilot/config.json` の `trustedFolders` にプロジェクトの絶対パスを追加する。未信頼だとフックが **警告なしで全部スキップ** されます。
- ヘッドレス `copilot -p` では加えて `GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=1`。
- `/aidlc --doctor` のあと `/aidlc <やりたいこと>`。

## 導入後の確認

init コマンドはありません。`aidlc config` が `aidlc/spaces/default/` を作ります。最初の `/aidlc` でアクティブスペースに intent が自動作成されます。

どちらのハーネスでも、セッション内で:

```text
/aidlc --doctor
/aidlc <作りたいものの説明>
```

マシン側の検査は `aidlc doctor` です。ランタイム、プロジェクト、フック、信頼を見ます。全部通れば exit 0、どれか落ちれば exit 1 です。

## アップグレード

```bash
aidlc update
cd your-project
aidlc doctor
aidlc config
```

- `aidlc update` はマシンのランタイムだけを更新します。プロジェクトは書き換えません。
- プラグインを使っている場合は、エンジン更新のあと必ず `/aidlc plugin sync` する。新しいランタイムは出荷時のステージグラフに戻るため、プラグイン合成が消えます。
- Claude Code は次回セッション開始時に compose hook で自己修復することもあります。確実にするなら明示的に sync します。
- スキル・ルールの変更は **新しいセッション** で読み込まれます。
- ワークフローが生きているあいだ、`aidlc config` は更新を拒みます。先に終えるかアーカイブします。

手で `runtime/<harness>/` をコピーする場合は、同じ版の `aidlc-runtime-X.Y.Z.tar.gz` から取ります。リポジトリの `dist/` は開発用の生成物です。

## よくあるつまずき

| 症状                                                | 対処                                                                       |
| --------------------------------------------------- | -------------------------------------------------------------------------- |
| 新しいシェルで `aidlc` が無い                         | インストーラが出した PATH を入れる                                         |
| Bedrock が `AccessDenied` / model-not-found         | アカウントでモデルアクセスを有効にし、認証と `AWS_REGION` を確認する       |
| Claude でフックが 0 件 / ポリシー制限               | 管理設定の `allowManagedHooksOnly`。プロジェクト側では解除できない         |
| Copilot でフックが動かない                          | フォルダ信頼。未信頼は無言でフック無効                                     |
| プラグインのステージが消えた                        | `/aidlc plugin sync`                                                       |
| 新しいランタイムのあとスキルが効かない             | セッションを作り直す                                                       |
| `aidlc config` が生きているワークフローで拒む         | 先にワークフローを終えるか `/aidlc intent archive` する                   |

生成物は必ず人が確認してください。モデルとエージェントの出力・コストは誤ることがあります。依存する環境では既知の良いバージョンをピンします。
