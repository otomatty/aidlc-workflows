# AI-DLC Workflows 導入方法

対象バージョン: **v2.7.0**（`main` が GA）。2026-09-01 時点の [awslabs/aidlc-workflows](https://github.com/awslabs/aidlc-workflows) に基づきます。

この文書は **Claude Code** と **GitHub Copilot** への導入手順だけをまとめたものです。使い方・段階・エージェントの詳細は文末の公式ガイドを見てください。他ハーネスは [Running on other harnesses](guide/harnesses/README.md) です。

## 導入の考え方

AI-DLC は **ハーネス（AI コーディング環境）にコピーして使う** 実装です。リポジトリの `dist/<harness>/` を、作業するプロジェクトへ入れます。エンジン本体は同一で、違うのはシェル（設定ディレクトリと起動方法）だけです。

| ハーネス       | 最低バージョン                     | コピー先の主なパス                          | 起動     |
| -------------- | ---------------------------------- | ------------------------------------------- | -------- |
| Claude Code    | （CLI 本体）                       | `.claude/` + `aidlc/`                       | `/aidlc` |
| GitHub Copilot | CLI ≥ 1.0.74 / VS Code ≥ 1.130 | `.aidlc/` + `aidlc/` + `.github/`（マージ） | `/aidlc` |

推奨モデルは **Claude Opus 4.8** です。弱いモデルではレビューや承認ゲートが省略されがちです。

## 共通の前提

どちらのハーネスでも **bun** が必要です。フックと CLI は bun で動きます。

```bash
# macOS / Linux
curl -fsSL https://bun.sh/install | bash
```

```powershell
# Windows PowerShell
irm bun.sh/install.ps1 | iex
```

```batch
:: Windows CMD（PowerShell インストーラを呼ぶ）
powershell -c "irm bun.sh/install.ps1 | iex"
```

Windows では PowerShell か CMD のどちらか一方を使います。WSL は不要です。Bash ツール向けに [Git for Windows](https://git-scm.com/downloads/win) を入れておくと安全です。

`which bun` は通るのにハーネスから見つからないときは、非対話シェルの PATH に bun がありません。インストーラは `~/.zshrc` に書きますが、ハーネスは `~/.zshenv`（zsh）または `~/.bashrc`（bash / Git Bash）を読むので、`BUN_INSTALL` と `PATH` をそちらへコピーします。

モデル認証はハーネスごとです。

- Claude Code: 配布設定は **AWS Bedrock**
- GitHub Copilot: GitHub ログインまたは BYOK

## ソースを取る

`cp` は **このリポジトリのルート** から実行します。GA の `main` を clone します。

```bash
git clone --branch main https://github.com/awslabs/aidlc-workflows.git
cd aidlc-workflows
```

フォーク（例: `otomatty/aidlc-workflows`）を使う場合も、中身は `main` の `dist/` をコピーする点は同じです。

## ハーネス別の導入

以下の `your-project` は、AI-DLC を入れたいアプリケーションのルートです。`aidlc/` はワークスペースシェルで、ハーネス用ディレクトリの **兄弟** です。中に入れてはいけません。`aidlc/spaces/default/memory/` が無いと `/aidlc --doctor` の workspace shell チェックが落ちます。

`.gitignore` が既にあるプロジェクトでは、ファイルごと上書きせず、配布ファイルの `# AI-DLC` 以降だけをマージします。無いときだけ配布の `.gitignore` をコピーします。

### Claude Code

Claude Code を入れます。

```bash
# macOS / Linux
curl -fsSL https://claude.ai/install.sh | bash
```

```powershell
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
```

```batch
:: Windows CMD
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

macOS なら `brew install --cask claude-code` でもよいです。`claude --version` で確認します。

プロジェクトへコピーします。

```bash
cp -r dist/claude/.claude/ your-project/.claude/
cp -r dist/claude/aidlc/   your-project/aidlc/
if [ ! -e your-project/.gitignore ]; then
  cp dist/claude/.gitignore your-project/.gitignore
fi
cd your-project && claude
```

セッション内で `/aidlc --doctor`、続けて `/aidlc <やりたいこと>`。プロジェクトフックの承認を求められたら承認し、**セッションを完全再起動**します。`/clear` では足りません。

配布の `.claude/settings.json` は Bedrock（`AWS_REGION=us-east-1`）です。初回前に AWS アカウントで Anthropic モデルアクセスを有効にし、SDK の認証チェーンにクレデンシャルを載せます。詳細は [Getting Started — AWS Bedrock Setup](guide/01-getting-started.md#aws-bedrock-setup) です。

### GitHub Copilot

Copilot CLI ≥ 1.0.74 および / または VS Code ≥ 1.130。1 回の導入で CLI と VS Code agent mode の両方に効きます。モデルピンは無く、サインインまたは BYOK です。

```bash
copilot --version
```

```bash
mkdir -p your-project/.aidlc your-project/aidlc your-project/.github
cp -R dist/copilot/.aidlc/.  your-project/.aidlc/
cp -R dist/copilot/aidlc/.   your-project/aidlc/
cp -R dist/copilot/.github/. your-project/.github/
cp dist/copilot/AGENTS.md    your-project/AGENTS.md
```

`.github/` は **マージ** です。配布物は `aidlc` 接頭辞付きなので、既存の workflows などは上書きしません。`AGENTS.md` をマージするときは `@`-import ブロックを残します。

コピー後にやること:

- `AGENTS.md` の `.gitignore` を入れる。
- フォルダを信頼する。対話プロンプトを承認するか、`~/.copilot/config.json` の `trustedFolders` にプロジェクトの絶対パスを追加する。未信頼だとフックが **警告なしで全部スキップ** されます。
- ヘッドレス `copilot -p` では加えて `GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=1`。
- `/aidlc --doctor` のあと `/aidlc <やりたいこと>`。

## 導入後の確認

init コマンドはありません。コピーした時点で `aidlc/spaces/default/` が入ります。最初の `/aidlc` でアクティブスペースに intent が自動作成されます。

どちらのハーネスでも、セッション内で:

```text
/aidlc --doctor
/aidlc <作りたいものの説明>
```

`--doctor` は bun、フック、ワークスペースシェル、グラフなどを検査します。全部通れば exit 0、どれか落ちれば exit 1 です。

## アップグレード

- 新しい `main`（またはタグ）を取り、同じ `cp` を再実行する。
- プラグインを使っている場合は、エンジン再コピーのあと必ず `/aidlc plugin sync` する。新しい `dist/` は出荷時のステージグラフに戻るため、プラグイン合成が消えます。
- Claude Code は次回セッション開始時に compose hook で自己修復することもあります。確実にするなら明示的に sync します。
- スキル・ルールの変更は **新しいセッション** で読み込まれます。

`dist/` は生成物です。手で編集せず、ソースを直したら `bun scripts/package.ts` で再生成します（メンテナ向け）。

## よくあるつまずき

| 症状                                                | 対処                                                                       |
| --------------------------------------------------- | -------------------------------------------------------------------------- |
| ターミナルでは bun があるがハーネスから見つからない | `~/.zshenv` または `~/.bashrc` に bun の PATH を入れる                     |
| Bedrock が `AccessDenied` / model-not-found         | アカウントでモデルアクセスを有効にし、認証と `AWS_REGION` を確認する       |
| Claude でフックが 0 件 / ポリシー制限               | 管理設定の `allowManagedHooksOnly`。プロジェクト側では解除できない         |
| Copilot でフックが動かない                          | フォルダ信頼。未信頼は無言でフック無効                                     |
| プラグインのステージが消えた                        | `/aidlc plugin sync`                                                       |
| 新しい `dist/` のあとスキルが効かない               | セッションを作り直す                                                       |

生成物は必ず人が確認してください。モデルとエージェントの出力・コストは誤ることがあります。依存する環境では既知の良いバージョンをピンします。
